# 持久用量、后台预算与历史保留（第二轮）

## 使用入口

- 设置中的模型供应商用量区：查看已知金额、未知条数、覆盖率、统计起点和截断提示；展开“持久用量预算与后台额度”设置全局每日、全局每月和每位助手的后台记忆每日额度。
- 记忆查看器的“待核实”页：展开“后台记忆额度与历史保留”，查看当前助手统计、暂停原因、学习开关状态、保留策略及整理结果。设置和整理与记忆编辑共用写锁，失败后可保留输入重试。
- 自定义模型编辑器支持每百万 token 的输入、输出、缓存读取和缓存写入价格。当前计算仅支持 USD，不猜汇率。保存需要确认来源；明确免费需要显式确认，缺失字段不是零。模型、API 或 endpoint 变化后需重新核价。价格变更会使旧工作流预算资格失效。

默认没有额度限制，也不自动归档历史。新增设置自身不会发出模型请求。

## 命令行

使用正在运行的本地服务以及 CLI 既有认证，不直接改数据库：

```sh
codia usage report
codia usage budget
codia usage budget set '{"daily":{"maxCalls":100},"monthly":{"maxUsd":10},"memoryDaily":{"maxCalls":10,"maxTokens":200000}}'
codia usage retention <agentId>
codia usage retention <agentId> set '{"completedExtractionDays":30,"ordinaryEventDays":90}'
codia usage retention <agentId> apply --confirm
```

`budget set` 替换整份预算配置；`{}` 取消额度限制。保留策略中的 `null` 禁用该项归档。天数允许 1–36500；预算仅接受有限非负数，调用次数与 token 必须为整数。0 会暂停对应维度。CLI 写入先读取当前版本；发生并发冲突时刷新报告后再决定是否重试，不自动覆盖别人的设置。

接口：`GET/PATCH /api/usage/budget`，`GET/PATCH/POST /api/memories/maintenance?agentId=...`。预算 PATCH 需 `config`、`expectedRevision`；保留 PATCH 需 `policy`、`expectedRevision`；整理 POST 需 `confirmed:true`、`expectedRevision`。使用现有 settings.read/settings.write 能力约束。

## 金额与用量口径

1. “已知部分”只相加可计算金额；未知费用单独统计，显示覆盖率。真正确定为零的费用显示 `$0.00`；未知不显示为免费。
2. 配置估算与供应商报告金额分开。SDK 根据模型费率计算的 cost 也是估算。任何一种都不等于已核对供应商账单。
3. 缺失 usage、SDK 自动产生的全零占位、无价格元数据的零金额都保留为未知。流式/传输失败或中断即使含正数 token，也只是部分观测，保存为 `reportedPartialUsage`，不当成完整最终用量结算。若宿主已完整读取成功的非流式 HTTP JSON，或收到 Codex `response.completed`，之后仅本地空文本校验失败，则保留 error 状态并按可靠最终 usage 结算。EOF、`[DONE]` 或 payload 自称 final 均不能代替完成证据；终态响应缺 usage 时也不能借用更早的 partial。
4. 完整成功用量按派发时的价格快照结算，不被过期会话价格、返回 payload 的零 cost 或后续改价覆盖。
5. 持久账本记录 request/agent/session/run/job 等可信运行归因。工作流使用现有 journal run ID，自动化使用本次 activity run ID 与 cron job ID；模型参数不能指定这些 ID。
6. 默认请求列表取最近 500 条，有明确截断信息；日期窗口单独查询。统计起点以前的旧运行不会凭空补齐，也不称作完整历史总额。

## 准入预留、并行与恢复

账本位于应用数据目录的 `usage/ledger.sqlite`。在模型派发前使用 SQLite 原子事务预留，跨连接/重启共享额度，普通会话、桥接、隔离任务、后台 summary/compile/fact/experience、压缩与快照侧任务共用此门。快照侧任务复用父预留前仍须验证当前 endpoint、费率及输出上限绑定，不能因去重跳过核验。

额度按 UTC 日/月计算；后台记忆每日额度对每位助手分别计数，目前所有助手使用同一份后台额度配置。为保守起见，token 预留使用模型上下文窗口加输出上限；金额预留同时要求输入、输出、缓存价格可计算，输入采用这些输入类别中的最高费率。实际短请求也可能需要较大的预留。

未知费用不会释放原预留。启用金额额度时，当前周期已有未知最终费用会暂停新的金额准入；只调高额度不能把未知变已知。价格不完整时，先核价；额度耗尽可调高额度或等待下个相关 UTC 周期。仍有全局月额度约束时，只跨日不会解除月约束。后台提取因预算不足暂停时保留任务并安排重试，不消耗失败重试次数、不因欠预算进入隔离。

“未结算（可能进行中或中断）”表示尚未收到最终结算：进程重启后保留完整预留，不推断请求仍活跃，也不批量将它们标为失败。当前没有可信 owner/liveness 检测、自动释放超时预留或供应商账单对账入口。配置窗口结束后不再计入新窗口，但历史仍保留。若需要处理中断运行，先核对供应商实际结果和应用记录，不能把重启视为费用清零。

这是本地模型准入控制，不是供应商账单硬上限。已发请求无法撤回结算；外部客户端调用、供应商实际计费规则及网络层重试等不受此处完整控制。

## 历史保留

- 成功提取过期后只压缩来源明细、旧错误/租约信息，永久保留来源修订、提取器版本和成功幂等收据。再次扫描同一来源不会重新收费提取。
- 仅有可信日期的普通 retrieved/injected 事件归档为幂等收据；统计仍包含收据，重复事件仍被拒绝。归档后收据仍占空间，不承诺把数据库完全缩小。
- 失败、未知、隔离、运行中提取；无日期旧事件；创建/复核/采纳/结果证据；tombstone、撤回和生命周期 journal 均不按普通 TTL 删除。
- 保存策略和手动整理使用 SQLite 跨进程锁，锁内读取最新策略并比较版本。手动确认后策略若已变化，返回冲突，不能用过期确认执行。后台维护同样锁定最新策略。文件采用原子替换；进程退出会释放数据库锁。
- 整理不重新启用已关闭的学习开关，也不恢复已撤回记忆。

## 安全与验证范围

持久账本对白名单模型/归因字段记账，不保存完整 SDK model、Authorization headers、API key 或 endpoint URL/query。模型绑定使用不可逆摘要；错误消息与价格来源作敏感文本脱敏。SQLite 回归检查包含合成秘密标记，确保凭据不进入待结算或已结算文档。

已验证真实 SDK 的离线合成 SSE（OpenAI 无 usage、Anthropic 有正数 partial 后中断）、真实 Agent 的准入拒绝与同步错误、真实侧任务/压缩调用、SQLite 多连接及独立 Node 进程、Hono 并发 API、CLI 处理和 React 交互。所有模型响应均为本地合成，无真实供应商请求、无新增付费调用。最终集成测试与打包结果见本轮验收记录；本文不声称已执行真实凭据/生产账单或完整桌面浏览器端到端验证。
