# Codia 原始代码对照与功能补全方案

本次将用户提供的 openhanako 0.450.0 源码包与当前 Codia 0.2.0 对照，重点检查之前出现问题的模型运行时、技能与文件引用、工作流草稿、欢迎页及助手设置。结论是保留 Codia 的品牌、导航和数据兼容设计，按调用链修复缺陷；助手协作已在后续实施中接通后端、独立只读审阅、主助手续答及历史协议（见文末新增验收）。

## 对照范围

原始包的 PI 三个依赖为 0.80.3，当前项目为 1.0.1。原版的组件、路由和 SDK 调用不能整体覆盖当前项目。原始包已解压到 `.tmp/original-review-20261006/openhanako-0.450.0`，本次改前文件副本保存在同目录的 `backups` 下。

对照覆盖关键调用链，不代表已经逐行审计整个仓库，也不代表原版所有能力都需要恢复。用户明确要求删除的阅读模式、顶栏页面导航、旧主题和独立图谱入口继续按当前设计处理。

## 当前功能与原版差异

文件及图片提及已有真实文件引用链路。本次修复的是菜单、输入法及草稿恢复。结构化草稿目前保持在应用内存中；这次没有新增跨进程草稿存储，也没有迁移用户会话。

最初检查时，助手提及仅插入名称。后续已改为结构化助手 ID，每轮选择一位辅助助手，在独立只读会话中审阅，再交回原助手完成任务。不会因选择 `@` 而切换当前会话身份。

当前工作流已接入独立页面和草稿，执行时才关联频道；知识图谱与思维导图继续作为聊天内嵌卡片。模型扫描已存在 GPT Image 分类与媒体模型入口，本次运行相关回归，不重复移植旧版扫描逻辑。

## 功能补全顺序

### 第一阶段 完成助手提及协作

保留当前会话助手，先实现每次请求一个辅助助手的审阅流程。前端徽章使用稳定助手 ID，发送结构化字段；服务端校验助手、请求归属和重复请求，并通过现有 detached session 底座创建只读审阅会话。审阅结果作为参考资料交回原助手，不作为用户或系统指令。

复用原版 `lib/agent-review/turn-coordinator.ts` 的职责划分，适配当前 `core/desktop-session-submit.ts`、聊天路由与 PI 1.0.1。补齐运行中、完成、失败和取消卡片，以及会话重新打开后的恢复。验收涵盖同名助手、已删除助手、重复提交、取消、失败、重启恢复和工作空间权限。全过程使用两个本机模拟模型端点验证。

### 第二阶段 补齐运行时诊断与历史边界

启动时检查必须存在的扩展，缺失时显示可定位的诊断。继续核对后台摘要、记忆及频道调用是否统一走当前 ModelRuntime。区分本地初始化错误、鉴权失败和供应商暂时性 500，避免无区分重试造成重复任务。

参考原版补齐压缩历史、保留历史与完整工具调用事务的边界检查，覆盖 split turn、thinking、工具结果和压缩后继续对话。新增 SDK 升级检查必须包含动态扩展注册、OAuth 和自定义端点，避免只验证类型与导入成功。

### 第三阶段 补齐助手管理与界面细节

在助手配置页补回紧凑的“导出助手”入口，连接现有角色卡导出接口，先展示预览并确认，默认不导出记忆。完善旧技能消息格式、引用代码块的识别测试，避免把用户自己粘贴的示例误当作内部消息。

继续检查五类设置的搜索路径、动态插件模块和键盘焦点；维持“通用与设备”位于“系统与安全”之后。低高度窗口允许欢迎内容滚动，输入框始终可见。有效视口缩放模拟通过后，还需真实 Windows 125% 显示缩放检查。

### 第四阶段 发布兼容验收

在隔离数据副本上完成旧版本覆盖安装、会话与密钥读取、浏览器登录、快捷方式、自启动及单实例检查。服务端构建中的可选 Hermes runtime 当前显示源文件缺失；如果产品需要该能力，需先补齐对应源码和打包资源，否则应明确隐藏不可用入口。

发布检查分别报告单元测试、Electron 冒烟、浏览器布局检查和安装验收。现有 `e2e:desktop-smoke` 只执行三个脚本；较完整的桌面业务回归使用 `node scripts/e2e-full-desktop-smoke.mjs`，也不能替代收费供应商的真实联网验收。

首次 Electron 集成检查发现了 Windows 长短路径错误，修复后会话刷新 API 返回成功。该短会话的结果为 `nothing_to_compact`，证明运行时恢复与刷新路径正常，不能据此声称长历史摘要端到端验收完成；长历史、取消和并发目前由针对性回归覆盖。

冒烟还发现模拟服务错误地把思维导图内部生成请求识别为外层工具调用，导致本地兜底。模拟器已按实际提供的工具列表分流，测试会在出现该兜底错误时失败，避免把兜底结果误算为模型结构化生成通过。

## 后续实施：快捷任务标签与助手审阅（2026-10-06）

四张首页卡片现在插入和技能徽章同一视觉风格的紧凑任务标签，支持删除。切换任务只替换任务标签，保留输入文字、技能和附件。输入标签使用固定 ID，任务说明由服务端解析，聊天记录和侧栏摘要不显示内部指令。

| 入口 | 发送后的实际行为 |
|---|---|
| 整理我的想法 | 按想法整理任务调用当前会话模型；正文保留用户文字。 |
| 开始编程协作 | 保留工作空间选择，携带当前工作空间和编程协作任务提交。 |
| 搭建一个工作流 | 用户填写描述后发送，进入现有模板生成器；结构校验通过后展示可编辑预览，用户确认才写入画布。失败保留原画布。 |
| 问问我的 Agent | 自动打开助手提及菜单；选择一位辅助助手后，独立只读审阅，再由原助手续答。 |

审阅实现与恢复：

- 通过稳定的助手／对话 ID 传递引用；会话引用由 manifest 解析为有长度限制的历史摘录，不再作为 JSONL 文件附件传给模型。
- 审阅共享当前模型与工作空间，保留原助手身份；记录进度、意见、错误、取消状态和原／审阅会话的双向入口。
- 父会话在整个审阅和续答期间保留执行占用；取消检查覆盖创建和交接阶段。相同请求 ID 的重传不会重复执行模型调用。
- 采用现有会话 JSONL 的自定义记录保存展示信息。PI 对只有自定义记录的新会话不落盘，因此在开始审阅时记录真实用户请求，确保首轮审阅失败、取消也能恢复；展示层合成为一个用户气泡。
- 修复审阅状态更新误用仅支持助手消息的更新方法；现在按请求 ID 更新用户气泡。修复 Windows 短路径／长路径造成审阅会话切换 403；目录校验继续拒绝越界路径。
- 原有技能 `/`、附件、输入工具、工作流草稿与用户真实配置继续沿用。未新增服务端接口。

本轮验证：

- 13 个相关测试文件，共 145 项回归通过，覆盖四种标签、引用、状态更新、历史投影、会话路径、工作流及取消／重复提交。
- 渲染器、Node、测试三套 TypeScript 检查通过；客户端完整构建与服务端构建通过。服务端 SQLite 运行检查、PI SDK 校验通过。仍有已有的动态导入拆包提示。
- Electron 原生窗口中完成 9 组检查：四条入口完整流程、失败后历史恢复、取消后不续答、无效模板不改画布、切换标签保留文字、三个尺寸布局（布局合为一组）。渲染器未捕获异常 0。
- Electron 运行使用两个隔离临时配置和自动分配端口，全部 16 次模型请求均为本机 `e2e-*` 模拟模型，没有调用收费模型。
